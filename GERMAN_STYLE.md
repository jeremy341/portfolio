# German editorial style

Write the German edition as if it had originated in German. English is the factual reference, not a sentence-by-sentence template.

- Keep the question, observation, surprise and conclusion behind every story. Dry humor works best with short sentences and occasional fragments; do not add jokes just to sound casual.
- Use first person and informal du (ihr when addressing readers as a group). Use a quieter, professional register for the CV and certificates.
- Prefer active verbs and concrete observations. Avoid literal calques such as "in Hardware bauen", "ehrlicher Stand", "Geldbereich" and "Systeme & Rechnen".
- Keep established technical terms: Machine Learning, Computer Vision, GPU-Computing, Backend, Frontend, Deployment, Stack, Shader, Live-Demo. Use Datensatz, Quantisierung, Inferenz, Objekterkennung, Mikrofluidik, Mikrocontroller, Quellcode and serielles Protokoll when they read naturally.
- Use German quotes „…“, decimal commas, percent spacing and correct compound hyphens in prose. Preserve actual code, filenames, identifiers and original UI strings.
- No inflated claims: keep measured results, uncertainty, denominators, dates and experimental status intact. Downloads are file requests, not people; TorchVK is a research plan.
- Project and article routes use the same slug in both languages. Preserve links, figure indexes, metadata and publication dates. Translate labels and captions; use the existing localized chart assets.
- Before merging run npm run check and npm test; inspect both mobile and desktop. Never change a claim solely to make a translation smoother.
